# Harness Release v1.8.24

## Summary

Makes bare `./harness run` the default external-controller autopilot loop and adds delete-safe retention cleanup for controller-owned smoke sidecars.

## Changes

- `./harness run` now repeatedly processes queued auto sidecar backlog transactions.
- Each successful transaction reuses existing gates: implementation, sidecar backlog completion, product local commit, and product push preflight/apply.
- `./harness run --once` processes one transaction and exits.
- Push remains fail-closed: remote/upstream/branch/dirty/drift blockers stop the loop after any safe local commit.
- Repeated failures are compacted into incident signatures under `targets/<id>/state/incidents/`.
- `./harness smoke implementation` deletes its temporary smoke sidecar by default; `--keep` preserves it for debugging.
- Added `./harness controller audit-size` and `./harness controller cleanup --dry-run|--apply` for controller-owned smoke/temp sidecars.

## Safety

- No product repo cleanup is performed by controller cleanup.
- Product commits and pushes still go through existing backlog-bound gates.
- Cleanup only removes delete-safe smoke/temp sidecars and writes a cleanup receipt.
