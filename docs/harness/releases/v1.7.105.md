# Harness Release v1.7.105

Release date: 2026-05-12

This release completes the Phase 4 routing contract for external controller Telegram/Redis owner commands. It does not enable product-changing `target run` execution.

## Changes

- Target-scoped relay drain validates `targets/<id>/target.json` and sidecar integrity before materializing owner instructions.
- External target instructions are written to `targets/<id>/operator-inbox`, not embedded `runs/autonomy/inbox`.
- Product bot relay can use `HARNESS_RELAY_TARGET_IDS` to require explicit `/harness <action> <target-id> ...` commands and reject unknown targets before enqueue.
- Relay target ids now fail closed on invalid syntax or reserved operand words instead of being normalized into another id.
- Controller CI/export coverage now includes target-aware Telegram bridge and Redis relay tests.

## Non-Goals

- `./harness target run <id> --once` still stops before autonomy lane execution.
- Product repos still do not receive harness state, inbox/outbox, reports, or secrets.
- Provider env mutation and global deployment changes remain outside this release.

## Verification

- Focused Telegram/relay/settings tests.
- Controller export check and controller bundle focused test coverage.
- Harness run validation and pre-push guard.
