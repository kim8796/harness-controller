# Harness v1.8.16

Release date: 2026-05-14

## Summary

Adds beginner `./harness finish` for the external controller post-run path. It keeps the advanced target backlog gates canonical while giving operators a short Korean command to inspect and apply the next safe stage.

## Operator Notes

- `./harness finish` is read-only and shows the latest matching implementation run, selected backlog, product diff paths, and next command.
- `./harness finish --apply` completes the sidecar backlog through the existing transition gate.
- `./harness finish --commit --message "feat: ..."` dry-runs the product commit gate; add `--apply` to create the local product commit.
- `./harness finish --push` dry-runs the product push gate; add `--apply` to update the registered remote.
- Product commits and pushes are still explicit. Telegram/Redis do not trigger finish, commit, or push.

## Safety

- Implementation evidence discovery is owned by `scripts/harness_controller.py`, not duplicated in the CLI.
- `finish` delegates all mutations to existing transition/commit/push gates.
- Product repo harness pollution remains blocked by target verification.
