# Harness Release v1.8.21

## Summary

- Reorganized the beginner documentation so `START_HERE.md` is a short entry point instead of a long mixed reference.
- Added dedicated docs for operator commands, task intake, Telegram/Redis setup, troubleshooting, and starter scaffold reference.

## Changes

- `docs/harness/START_HERE.md` now routes readers by situation and keeps the main external controller quick start near the top.
- `docs/harness/OPERATOR_GUIDE.md` covers daily commands, run/finish, smoke checks, and release-check usage.
- `docs/harness/TASK_INTAKE.md` covers request drafts, external editing, images, review, advisory AI review, and queue rules.
- `docs/harness/TELEGRAM.md` covers operator env, target selectors, `/harness` grammar, and compact outbox expectations.
- `docs/harness/TROUBLESHOOTING.md` covers common install/run/Telegram/release-check blockers.
- `docs/harness/STARTER_SCAFFOLD.md` keeps the file structure and scaffold reference that used to make `START_HERE.md` hard to scan.
- Export source lists and export tests now include the new guide documents.

## Safety

- No runtime behavior changed.
- No Telegram/Redis, target execution, product commit, product push, or env mutation behavior changed.
- The change only reorganizes docs and keeps `START_HERE.md` linked to the detailed reference docs.
