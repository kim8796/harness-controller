# Harness v1.8.12

Release Date: 2026-05-14

## Summary

`v1.8.12` adds the explicit backlog-bound product push gate for external controller targets. It completes the local-diff -> sidecar transition -> local commit -> remote push sequence without making Telegram, backlog transition, or commit creation implicit.

## Changes

- Added `./harness target backlog push <target> --run <implementation-run>`.
- Kept the command dry-run by default; `--apply` is required for a product remote push.
- Required a matching applied backlog product commit receipt, clean product repo, completed sidecar backlog metadata, matching implementation evidence, and registered branch upstream.
- Required the remote branch head to still match the recorded pre-commit product HEAD before pushing.
- Recorded product push receipt, generated evidence, and report under the target sidecar when apply succeeds.

## Safety

- No force push, tags, broad refspecs, or automatic remote rollback.
- No product commit creation in the push command.
- No sidecar backlog state mutation in the push command.
- No Telegram-triggered product push.
- Product repo harness state pollution remains blocked by the target verification path.
