# Harness Release v1.8.25

## Summary

Makes Telegram/Redis relay drain portable by moving the Upstash store adapter into the controller bundle and tightening target-scoped external drain behavior.

## Changes

- Added `scripts/harness_relay_store.py` as the controller-owned Upstash relay store adapter.
- Removed the bridge dependency on external app `db.database.RedisStore`.
- Added `python3 scripts/harness_telegram_bridge.py --drain-relay --target-id <target> --json` for manual target-scoped drain smoke checks.
- External controllers with registered targets now reject unscoped state-changing relay drain instead of materializing to root `runs/autonomy/inbox`.
- `./harness env check --provider vercel` and `env register --provider vercel --dry-run` now include target-aware relay keys without printing values.
- `./harness telegram setup --dry-run` now gives a controller readiness view for Telegram setup without mutating env/provider/webhook/deploy state.
- Starter/controller exports include the relay store adapter and focused tests.

## Safety

- Telegram remains an owner-instruction transport only; it does not run `./harness`, commit, push, or transition backlog directly.
- Relay envelopes and Redis keys continue to use canonical target ids, not aliases.
- Missing Upstash client/env or adapter errors fail closed without logging secret values.
- Telegram setup readiness output includes env key names and redacted status only.
- Product repositories are not mutated by relay drain or controller export.
