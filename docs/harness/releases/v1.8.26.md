# Harness v1.8.26

Release Date: 2026-05-16

## Summary

Adds a corrected Telegram setup wizard for external controllers. The wizard keeps dry-run fail-closed, redacts secrets, writes only ignored env overlays, separates Vercel env sync from deploy, and verifies Telegram webhooks before reporting success.
It also makes beginner `./harness run` drain queued work and exit cleanly when the queue is empty, while preserving continuous polling behind explicit `--watch`.

## Changes

- Added `./harness telegram setup` with `--dry-run`, `--apply`, `--apply-gateway-env`, `--apply-vercel`, `--deploy-vercel`, and `--set-webhook` stages.
- Removed destructive Vercel env removal from setup automation; overwrites require `--force-vercel-env`.
- Kept tracked `.env.example` updates as code/docs changes only; runtime gateway env writes target ignored secret env files.
- Standardized gateway operator allowlist on `HARNESS_TELEGRAM_OPERATOR_USER_IDS`.
- Changed bare `./harness run` to exit on an empty queue and added `./harness run --watch` for long-running polling.
- Added focused controller and downstream relay contract tests for setup safety.

## Safety

- `--dry-run` overrides every apply/deploy/webhook flag and performs no file, Vercel, Telegram, or Upstash side effects.
- Raw bot tokens, signing keys, Upstash tokens, webhook secrets, and chat ids are not emitted in stdout, JSON, or step data.
- Telegram remains an owner-instruction transport only; controller drain materializes target-scoped inbox markdown at safe points.
