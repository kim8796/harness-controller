# Harness v1.8.0

Release date: 2026-05-13

## Summary

External controller targets now have RootContext-aware autonomy state plumbing. `target run --once` remains a read-only/no-op smoke: it proves registered target boundaries and writes harness state only to the controller sidecar, while product-changing lane execution stays disabled.

## Changes

- Added external autonomy context resolution for `controller_root`, canonical `target_id`, `target_root`, and `state_root`.
- Made external `run-once` load the target registry instead of trusting raw hidden paths.
- Wrote sidecar evidence under `targets/<id>/runs/harness`, reports under `targets/<id>/reports/harness-autonomy`, operator outbox under `targets/<id>/operator-outbox`, and control/runtime under `targets/<id>/state`.
- Routed external CLI `send` to `targets/<id>/operator-inbox` instead of embedded `runs/autonomy/inbox`.
- Kept `./harness target run --once` locked and product-clean while adding autonomy state plumbing evidence.

## Safety

- Product-changing lane execution, commit, push, PR, and merge remain disabled.
- Dirty targets, detached HEAD, branch mismatch, missing sidecar, and embedded harness markers fail closed.
- Sidecar writes reject nested symlinks and path escape.
- No new backlog, inbox, outbox, proposal, relay, or cleanup ledger was introduced.
