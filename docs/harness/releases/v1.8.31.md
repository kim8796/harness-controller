# Harness v1.8.31

Release date: 2026-05-18

## Summary

This release adds controller-owned Operator-Wait runtime support and absorbs selected operating discipline into Harness policy. Beginner usage remains `install -> goal -> watch`; operator-wait is an internal watch state, not a new command.

## Changes

- Added `scripts/harness_operator_wait.py` and `tests/test_harness_operator_wait.py` to export allowlists and export tests.
- Added bounded operator-wait records under `targets/<target-id>/operator-waits/` as controller sidecar artifacts for external blockers.
- Projected credential-blocked publication and operator-actionable transaction failures into `watch/latest` and local `operator-outbox` cues.
- Extended incident classification with `operator_actionable`, `wait_class`, and `resume_policy` metadata.
- Hardened incident/operator-wait redaction and sidecar containment for Telegram tokens, private chat/operator ids, and symlinked state parents.
- Clarified that approvals, credential fixes, and transient waits resume only through existing Harness gates and never bypass secret, product-write, or publication checks.
- Rephrased the absorbed operating discipline as Harness policy around planning, first-boundary diagnostics, generated evidence, and explicit completion receipts.
